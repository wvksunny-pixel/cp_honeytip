GPT (ChatGPT)

레시피를 쓰는 기획 파트너

  • 내가 일상 말투로 설명한 요구를 구체적인 작업 지시서(프롬프트)로 정리
  • 페이지 구성·디자인·검수 항목을 빠짐없이 챙겨줌
  • 내 컴퓨터의 파일을 만들거나 고치지 않아요
→프롬프트를
복사해서 전달

Claude Code

레시피대로 만드는 작업자

  • 내 작업 폴더의 자료를 직접 읽고, 웹페이지 파일을 생성·수정
  • 실행해 보고 오류를 고치며 결과를 보고
  • 내가 허락한 폴더 안에서, 내가 지시한 범위만 작업

GPT가 웹페이지를 자동으로 만들어주는 게 아니에요. GPT는 “무엇을 어떻게 만들지”를 글로 정리하고, Claude Code가 그 글을 보고 실제 파일을 만듭니다.

Claude Code 설치하기

📌 사전 숙제! 1-1, 1-2(설치·확인)는 세션 들어오기 전에 꼭 해와 주세요. 숙제 목록 보기

작업자를 부엌에 모셔오는 단계예요. 아래 명령어는 Claude Code 공식 설치 문서를 기준으로 정리했어요(2026년 10월 확인). 설치 방법은 바뀔 수 있으니, 막히면 공식 문서를 먼저 확인해 주세요.

시작 전 확인
  • Claude Code는 Pro·Max·Team·Enterprise 또는 Console 계정이 필요해요. 무료 claude.ai 플랜에는 포함되지 않아요. 팀에서 쓰는 계정 정책을 먼저 확인해 주세요.
  • 회사 PC는 보안 정책상 설치가 막힐 수 있어요. 이럴 땐 IT 담당자에게 문의하세요.
1-1

설치 방법 고르기

터미널이 처음이라면 → 마우스로 쓰는 Claude 데스크톱 앱의 Code 기능으로 시작해도 좋아요. 명령어 입력 없이 폴더를 고르고 대화할 수 있어요.

터미널로 설치한다면 → 내 컴퓨터에 맞는 탭을 골라 명령어를 붙여넣으세요.

시작 메뉴에서 “PowerShell” 검색 → 실행. 화면에 PS C:\...>가 보이면 PowerShell이에요. 관리자 권한은 필요 없어요.

irm https://claude.ai/install.ps1 | iex

시작 메뉴에서 “cmd” 검색 → 실행. 앞에 PS 없이 C:\...>만 보이면 CMD예요.

curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

Spotlight(⌘+Space)에서 “터미널” 검색 → 실행.

curl -fsSL https://claude.ai/install.sh | bash

설치 중에는 진행 표시가 없어요. 끝날 때까지 잠시 기다려 주세요. Windows에서는 Git for Windows 설치가 권장(선택)이에요. 오류가 나면 설치 문제 해결 문서를 참고하세요.

1-2

설치 확인하기

터미널 창을 새로 연 뒤 아래를 입력하세요. 버전 번호가 나오면 성공이에요.

claude --version

“claude를 찾을 수 없다”는 메시지가 나오면 터미널을 껐다 다시 켜 보고, 그래도 안 되면 공식 문제 해결 문서의 PATH 안내를 따라 주세요.

1-3

작업용 폴더 준비하기

결과보고 하나당 폴더 하나를 만들어요. 예: 배민2026_결과보고. 폴더 이름은 짧고 알아보기 쉽게! (2단계에서 안을 채워요)

1-4

그 폴더에서 Claude Code 열기

방법 A. 터미널 — 작업 폴더로 이동한 다음 claude를 입력해요. 처음 실행하면 브라우저가 열리며 로그인을 안내해요.

cd "C:\Users\내이름\OneDrive\배민2026_결과보고" claude

💡 Windows 탐색기에서 폴더를 연 뒤 주소창에 powershell을 입력하고 Enter를 누르면 그 폴더에서 바로 PowerShell이 열려요. 경로는 내 PC에 맞게 바꿔 주세요.

방법 B. VS Code — 파일과 화면을 같이 보고 싶다면 VS Code 확장 안내를 따라 설치한 뒤, 파일 → 폴더 열기로 작업 폴더를 열어 사용하세요.

방법 C. 데스크톱 앱 — 앱에서 작업 폴더를 선택해 시작해요.

1-5

OneDrive 폴더 ↔ 작업 폴더 관계 이해하기

OneDrive (창고)팀 자료가 쌓여 있는 곳. 웹 OneDrive·Teams에만 있는 파일은 Claude Code가 볼 수 없어요.
PC에 동기화된 폴더만 →
작업 폴더 (조리대)Claude Code를 실행한 폴더. Claude Code는 기본적으로 이 폴더 안에서 일해요.

OneDrive 파일이 Claude Code에 “자동 연결”되는 게 아니에요. 내 PC의 파일 탐색기에서 실제 경로(예: C:\Users\내이름\OneDrive\...)로 열리는지, 파일이 “온라인 전용(구름 아이콘)” 상태는 아닌지 확인해 주세요. 필요하면 파일을 우클릭 → “항상 이 장치에 유지”를 선택하세요.

OneDrive는 사업 자료를 모아두고 팀원들이 함께 쓰는 창고예요. 이번 실습에서는 교육용 가상 예시 ‘배민 2026 도시락 사업’으로 연습해요. (실제 사업이 아닌, 연습을 위해 만든 가상 사례예요.)

재료 체크리스트 0 / 8

체크 상태는 이 브라우저에만 저장돼요.

폴더 구조 예시

배민2026_결과보고/
├─ input/            ← 재료 (원본은 복사본으로!)
│  ├─ business_plan/ 사업계획서
│  ├─ results/       결과보고·실적 정리
│  ├─ photos/        현장 사진
│  └─ data/          엑셀·학교 위치 정보
├─ output/           ← 완성된 웹페이지
└─ README.md         ← 이 폴더 설명서

이 구조는 예시예요. 이미 쓰고 있는 OneDrive 폴더 구조가 있다면 그대로 두고, Claude Code에게 “자료는 ○○ 폴더에 있어”라고 경로만 정확히 알려줘도 돼요.

꿀팁 · 원본 파일은 건드리지 않도록 복사본을 input에 넣어 두세요. · 파일 이름에 날짜와 내용을 넣으면(예: 2026_실적집계_최종.xlsx) AI도 사람도 헷갈리지 않아요.

⚠️ 아동 보호·개인정보 주의

  • 실제 아동의 이름, 얼굴이 식별되는 사진, 학교·학급, 주소 등 식별정보가 외부 공개 페이지에 나가지 않게 해 주세요.
  • 사진은 사용 동의와 기관의 아동보호 정책을 확인한 것만 사용해요. 필요하면 뒷모습·손·단체 원경 사진을 쓰거나 모자이크해요.
  • 사례(스토리)는 가명을 쓰고, 나이·지역 등 조합하면 특정될 수 있는 정보도 줄여요.
  • 후원자 개인정보, 내부 예산 상세, 협약 조건 등 대외비 자료는 input 폴더에 넣지 않는 것이 가장 안전해요.

그림 먼저 그리고, 퍼즐을 맞춘다

저는 일단 머릿속에 그림부터 그려요. 그리고 그 그림을 완성하려면 어떤 조각이 필요한지 하나씩 찾아가는 편이에요. 이름하여 선영식 바이브코딩입니다.

🖼️ 제가 그리는 최종 장면

기업 담당자가 결과보고를 넘기다가
“와, 월비 진짜 디테일하게 일했네. 우리가 후원한 사업을 이렇게 구체적으로 관리하고 있었구나!”

이 반응을 얻으려면, 결과와 사진을 쭉 늘어놓는 것만으로는 조금 부족하겠죠. 결과보고가 예뻐 보이는 것과 정말 일을 잘했다는 게 전달되는 것은 조금 다른 이야기니까요.

그래서 거꾸로 생각해봐요. “그러려면…”

  • 사업을 어떤 순서로 기획하고 실행했는지 보여줘야겠네
  • 단계마다 누가 무엇을 했는지 드러나면 더 구체적이겠네
  • 진행하면서 무엇을 확인하고 관리했는지도 보여주면 좋겠네
  • 주요 일정은 타임라인으로 정리하면 한눈에 들어오겠네
  • 결과만이 아니라 결과에 이르는 과정도 보여줘야겠네
  • 성과는 수치와 현장 사례를 같이 보여주면 더 설득력 있겠네

    배민 2026 도시락 지원사업의 결과보고를 제작하려고 해.
이 결과보고의 핵심 목적은 기업 담당자가 사업이 체계적으로 기획되고 실행되었으며, 진행 과정과 성과가 구체적으로 관리되었다는 점을 이해하도록 하는 거야.
먼저 원본 자료를 검토해서 실제 확인 가능한 사업 배경, 진행 단계, 일정, 참여 기관, 지원 현황, 성과 데이터를 파악해줘.
그다음 사업의 기획부터 결과까지 이어지는 흐름을 구성하고, 각 단계에서 무엇을 했는지 구체적으로 보여줄 수 있도록 챕터를 설계해줘.
진행 과정은 타임라인 또는 프로세스 다이어그램으로, 학교별 지원 현황은 검증된 위치 정보를 바탕으로 지도와 데이터 카드로, 주요 성과는 핵심 수치와 현장 사례로 표현하고 싶어.
단순히 화면을 예쁘게 만드는 것보다, 각 화면이 어떤 메시지를 전달하는지 먼저 설계해줘.
자료가 부족한 부분은 임의로 채우지 말고 추가로 필요한 자료를 알려줘. 확인된 정보와 가상의 예시를 명확히 구분해줘.
우선 자료를 검토하고 페이지 구성안을 제안한 뒤, 내가 방향을 확인하면 실제 웹페이지를 구현해줘.

    마이크로 수정의 기술
    
    
    “처음부터 완벽한 결과물을 만들려고 하지 마세요. 초안을 확인하고, 마음에 들지 않는 부분을 하나씩 구체적으로 수정하면 됩니다.”
    

    
    
      
    
        
    01 · 디자인
    
        
    전체적으로 조금 더 깔끔하게 바꿔줘. 월드비전 오렌지를 포인트 컬러로 사용하고, 여백을 넉넉하게 만들어줘.
    
        
      
    
      
    
        
    02 · 문장
    
        
    보고서 문체는 유지하되 문장을 더 간결하게 바꿔줘. 원본에 없는 성과를 추가하지 마.
    
        
      
    
      
    
        
    03 · 사진
    
        
    사진 크기를 키우고, 사진 아래에 활동 내용과 설명을 배치해줘. 실제 사진의 맥락을 확인하고 캡션을 작성해줘.
    
        
      
    
      
    
        
    04 · 지도
    
        
    지도에 참여 학교를 표시하고, 학교를 클릭하면 학교명과 해당 학교의 실적을 확인할 수 있게 해줘. 위치 정보가 없는 학교는 임의로 좌표를 만들지 마.
    
        
      
    
      
    
        
    05 · 데이터
    
        
    핵심 수치를 한눈에 볼 수 있게 카드로 만들어줘. 원본 데이터와 합계가 일치하는지 확인하고, 불일치가 있으면 알려줘.
    
        
      
    
      
    
        
    06 · 레이아웃
    
        
    메인 화면은 짧게 구성하고, 자세한 내용은 챕터별로 나눠줘.
    
        
      
    
      
    
        
    07 · PDF
    
        
    웹페이지를 PDF로 저장했을 때도 글자나 사진이 잘리지 않도록 인쇄용 스타일을 점검해줘.
    
        
      
    
      
    
        
    + 나만의 수정
    
        
    현재 문제 + 원하는 결과 + 유지할 것
    예) “2챕터 그래프 글씨가 너무 작아. 모바일에서도 읽히게 키워줘. 색상과 순서는 지금처럼 유지해줘.”
    
      
    
    
    

    
    
      
    마이크로 수정도 그림을 기준으로
    
      
    “예쁘게 바꿔줘” 대신, 처음 그린 그림과 지금 화면이 어디서 어긋났는지부터 봐요. 무엇을 바꿀지와 함께 왜 바꾸는지를 말하면 AI도 훨씬 정확하게 고쳐줘요.
    
      
      
        
    1. 원래 의도처음 그린 그림
      2. 
        
    2. 현재 문제그림과 어긋난 곳
      3. 
        
    3. 구체적인 수정 요청유지할 것 + 바꿀 것
      4. 
        
    4. 결과 확인그림에 가까워졌나?
      5. 
      
    

      
    
        
    원래 의도사업이 정말 체계적으로 진행됐다는 인상을 주고 싶다.
    
        
    현재 문제지금은 결과 수치만 있고, 그 수치가 만들어지기까지 어떤 과정을 거쳤는지 보이지 않는다.
    
        
    수정 요청현재 핵심 성과 카드와 디자인은 유지해줘. 대신 사업의 기획부터 실행, 현장 확인, 결과 정리까지 이어지는 과정을 추가해줘. 각 단계에서 실제 자료로 확인되는 활동과 일정만 표시하고, 전체 흐름이 한눈에 들어오도록 타임라인으로 구성해줘.
    
        
    결과 확인타임라인을 보고 “아, 이렇게 관리했구나”가 느껴지는지, 일정이 원본과 맞는지 직접 확인!

    참고하기 · 작업 방식 비교
    
    
    그림 먼저 vs 빠른 초안, 둘 다 정답입니다
    
    
    저는 그림부터 그리는 편이지만, 일단 만들어보고 보면서 키워가는 방식도 충분히 좋아요. 일의 성격이나 내 성향에 따라 편한 쪽을 고르면 됩니다.
    

    
    
      
    
        
    방법 A · 선영식
    
        
    “저는 일단 머릿속에 그림부터 그려요!”
    
        
    기업 담당자가 결과보고를 보고 어떤 인상을 받았으면 좋겠는지 먼저 생각해요. 그다음 그 인상을 만들려면 어떤 정보와 장면이 필요한지 역으로 찾아갑니다.
    
        
    최종 그림 상상필요한 정보 찾기챕터 구성프롬프트 작성구현·수정
    
        
    이럴 때 잘 맞아요
    
        
      
          
    • 결과보고의 목적과 독자가 명확할 때
      • 
          
    • 보여줘야 할 핵심 성과와 메시지가 분명할 때
      • 
          
    • 프로세스·데이터·사례 등 구성요소가 많을 때
      • 
          
    • 기업에 전달할 결과물의 완성도와 설득력이 중요할 때
      • 
        
    
        
    완성된 그림을 먼저 상상하고, 그 그림에 필요한 퍼즐을 맞춘다!
    
      
    
      
    
        
    방법 B · 빠른 초안형
    
        
    “일단 만들어보면 생각보다 답이 보일 수도!”
    
        
    처음부터 모든 구성을 정하려고 애쓰기보다, 일단 초안을 만들어보고 실제 화면을 보면서 더하고 빼는 방식이에요.
    
        
    간단한 아이디어초안 만들기화면 확인개선점 찾기반복 수정
    
        
    이럴 때 잘 맞아요
    
        
      
          
    • 무엇을 만들지 아직 막연할 때
      • 
          
    • 아이디어를 빠르게 눈으로 확인하고 싶을 때
      • 
          
    • 정답이 없어 여러 디자인을 실험해보고 싶을 때
      • 
          
    • 직접 만들어보는 과정에서 영감을 얻는 편일 때
      • 
        
    
        
    일단 만들어보고, 눈에 보이는 결과물을 보면서 방향을 찾아간다!
    
      
    
    
    
    
    저는 그림부터 그리는 편이지만, 무조건 제 방법을 따라 하실 필요는 없어요. 항빈님의 비개발자의 웹페이지 제작기 꿀팁도, 일단 만들어보는 방식도 모두 좋습니다. 본인에게 편한 방법으로 시작해보세요!
    

    
    
      
    📎 함께 보면 좋은 가이드
    
      
    위에 링크한 비개발자의 웹페이지 제작기에 이미 꿀팁이 가득해요. 자료는 채팅창 대신 폴더에 넣기, 바로 만들지 말고 구성안부터 받기, “없으면 없다고 말해”까지 못박기, 진짜 지도 넣는 법, 모바일 확인, 브랜드 파일, 개인정보·대외 공개 주의, 링크로 게시하기까지요. 이 가이드에서는 그 내용을 반복하지 않고, 그 위에 “무엇을 보여줄지 먼저 그리는 법”을 더했어요.
    
    
    
  
    

    



    
  
    
    
    참고하기 · 제작 예시
    
    
    배민 2026 도시락 지원사업에 적용해보면
    
    
    교육용 가상 예시 화면 구성을 설명하려고 만든 가상 사례예요. 실제 배민 사업의 사실이나 실적이 아니에요. 진짜 결과보고에서는 원본 자료로 확인된 정보만 씁니다.
    

    
    
      
    🖼️ 처음 떠올린 그림
    
      
    “기업 담당자가 결과보고를 보고 ‘우리가 후원한 사업이 이렇게 체계적으로 진행됐구나!’라고 느꼈으면 좋겠어.”
    
    
    

    
    이 그림을 다섯 조각으로 나눠볼게요 ↓
    
    
    
      
    
        
    🧩 퍼즐 1
    
        
    사업을 왜 시작했나요?
    
        
    • 사업의 배경과 목적
    • 기업 후원과 사업 목표의 연결
    • 해결하고자 했던 문제
    
        
    화면으로는 → 프롤로그 + 핵심 문장 한 줄
    
      
    
      
    
        
    🧩 퍼즐 2
    
        
    어떻게 진행했나요?
    
        
    • 기획부터 실행까지의 단계
    • 단계별 주요 활동
    • 일정과 담당 주체
    • 진행 중 확인·관리 절차
    
        
    화면으로는 → 타임라인 / 프로세스 다이어그램
    
      
    
      
    
        
    🧩 퍼즐 3
    
        
    어디에서 진행했나요?
    
        
    • 참여 학교의 위치
    • 학교별 활동 내용
    • 학교별 지원 현황
    
        
    화면으로는 → 지도 + 학교 클릭 시 정보 카드
    
      
    
      
    
        
    🧩 퍼즐 4
    
        
    어떤 결과가 있었나요?
    
        
    • 지원 규모와 주요 성과
    • 정량 데이터
    • 현장 사례와 사진
    • 사업으로 확인한 변화
    
        
    화면으로는 → 핵심 수치 카드 + 사진 사례
    
      
    
      
    
        
    🧩 퍼즐 5
    
        
    그래서 무엇이 달라졌나요?
    
        
    • 사업의 의미
    • 기업 후원과 연결되는 성과
    • 다음 사업에 참고할 시사점
    
        
    화면으로는 → 요약 카드 + 감사 인사
    
      
    
    
    

    
    
      
    
        
    퍼즐 3 화면 설계 예시: 지도는 이렇게
    
        
    진짜 지도가 아니라 설계 예시예요. 점을 눌러보세요. 학교명·수치는 모두 가상입니다.
    
      
    
      
    
        
    
          
          
          
          
          지도 영역 (실제 구현 시 Leaflet 같은 지도 라이브러리 사용)
        
    
        
    
          
    
            
    ← 학교 점을 눌러보세요
    
          
    
          
    
            📍 위치 확인 필요 (지도에 표시 안 함)
            
    가상 학교 E: 원본 자료에 주소가 없어서 임의로 좌표를 만들지 않고 목록으로만 보여줘요.
    
          
    
        
    
      
    
    
    

    
    
      
    그냥 “예쁜 홈페이지 만들어줘”가 아니에요. 내가 보여주고 싶은 그림을 먼저 정하고, 그 그림에 어떤 정보가 필요한지 생각하는 거예요.

      2. 공식 설치 문서 확인 — 설치 명령어를 지어내지 않도록 Claude Code 공식 문서를 직접 열어 대조
        3. 
          
      3. 파일 작성 — 페이지(index.html), 디자인(css), 동작(js), 설명서(README.md)
        4. 
          
      4. 브라우저로 열어 점검 — 스타일 선택, 프롬프트 자동 생성, 복사 버튼, 체크리스트가 실제로 되는지 확인
        5. 
          
      5. 문제 발견·수정 — 휴대폰 화면에서 설치 안내가 화면 밖으로 넘치는 걸 찾아서 고침
        6. 
          
      6. 결과 보고 — 여는 방법, 파일 위치, 아직 확인 못 한 점까지 알려줌
        7. 
        
      
        
      Claude Code의 답변 문장을 그대로 옮긴 게 아니라, 실제로 진행된 일을 요약했어요.

      → 지금 보고 계신 이 ‘제작기’ 섹션이 생김.

      → Claude Code가 참고 가이드를 브라우저로 열어 확인한 뒤, 겹치는 내용은 링크로 넘기고 그림 먼저 생각법(그림 먼저 5단계, 배민 예시, 두 가지 방식, 내 스타일 고르기·설계 워크시트)과 의도 기반 마이크로 수정을 추가함.
